# Audit — the Strava upload path — 2026-09-08

Run against main @ `6b9d5ce3`. Read-only, and read in a stricter sense than usual: **code and schema
only**. Per AGENTS.md's hard rule — Strava's API Policy §5.3 bans Strava Data in the development,
evaluation or operation of an AI application — no Strava payload was fetched, read or reproduced,
and the Strava API tooling available in the session was deliberately not used. Nothing was verified
in a running app.

**Produced one issue, [#1158](https://github.com/natrontech/wattroom/issues/1158).**

## The brief

Slice: `internal/strava` — the delivery record, the sweep, the upload and its status poll, and the
grant revocation.

Chosen because it was the last thing any audit had named and none had covered: the
[durable-privacy pass](2026-09-08-durable-privacy.md) and the
[riding-path pass](2026-09-08-riding-path.md) both listed it as untouched.

Excluded: the credential half — sealing, the refresh token, `identities` —
which [#1038](https://github.com/natrontech/wattroom/issues/1038) already owns and which is
correctly blocked on a check against the production database.

## The finding

**[#1158](https://github.com/natrontech/wattroom/issues/1158)** — a transient Strava failure
becomes a permanent one in under an hour, and the retry path makes the failure more likely.

Three small things compound:

1. **`await` never checks the HTTP status.** A 429 or 5xx decodes to a zero-value struct, which the
   loop reads as *"still processing"*. At `pollEvery = 2s` inside a 90 s budget that is ~45 further
   requests, per delivery, aimed at an endpoint that has just said stop. `post` checks its status
   twenty lines earlier and is the model.
2. **Nothing handles a rate limit.** A 429 is an ordinary error and spends an attempt.
3. **The ceiling arrives in ~50 minutes.** `maxAttempts = 5` with an `attempts × 5m` backoff, and a
   failed row leaves `pending` so the sweep never sees it again. The comment claims "retried over
   hours".

There is no retry control, and the rider is told to reconnect Strava — which is not what went
wrong.

The shape worth remembering: the recovery mechanism is what causes the permanent loss. A backlog
only exists after an outage, and draining it at 20 deliveries a minute with unchecked polls is what
provokes the limit that burns the attempts.

## What was checked, and found sound

| Claim | Verdict |
| --- | --- |
| The path is upload-only | `post`, `await`, `refreshToken`, `RevokeGrant` — nothing fetches activities, athlete data or segments. The only thing that comes back and is stored is the activity id of the ride we sent |
| No Strava Data is retained | `ride_exports.remote_id` is that id and `last_error` is an API error string. Neither is athlete data from Strava |
| `post` validates its response | `strava.go:362` — a non-201/200 is an error carrying a bounded snippet |
| Upload work never blocks a save | `RideSaved` runs on its own goroutine with its own budget; the save transaction is long done (#799) |
| A restart does not lose a delivery | The outcome is a row, not a goroutine's memory, and the sweep picks up what the process dropped |
| The rider's choice is honoured | `upload` returns early when `StravaUpload` is false — no record, no retry, no log |
| Revocation is done properly | `oauth/revoke` rather than the retiring `deauthorize` (#1093): the token travels in the form body and the *client* authenticates with Basic auth, so no token is ever written into a URL a proxy would log. It refreshes first, because revoke answers 200 whether or not it recognised the token — so revoking a token we merely believe in would report success while the grant lived on |
| Backoff is off an injectable clock | `s.now` throughout, so the sweep's timing is testable rather than wall-clock-bound |

The revocation comment is the best-reasoned code read in any of today's four audits: it names the
failure mode that would have been invisible (a silent 200 on an unrecognised token) and designs
against it.

## What was not covered

The credential half, per the exclusion above. The `.fit` bytes themselves — `encode` and
`internal/fitexport` were read in the [riding-path pass](2026-09-08-riding-path.md), which confirmed
heart rate belongs there as the rider's own durable ride (ADR-0008). Nothing was uploaded, so this
says nothing about how Strava actually answers.
