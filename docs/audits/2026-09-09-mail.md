# Audit: everything the server mails (2026-09-09)

**Slice.** `server/internal/notify/` (transport, the one template, the planned/moved/cancelled session mails and the hour-before reminder with its claim, the security alarms), the confirm-address and unsubscribe pages, the unsubscribe token and route, the notify settings on `/api/me`, the resend window, and ADR-0030's contract.

**Excluded.** The sign-in flow itself (its own audit the same evening), DMs, rooms, rides, Strava, the desktop shell. Open decisions reported, not re-decided (#1485, #1493).

**Method.** One read-only Explore agent at `42c52583`+ against ADR-0029/0030, WATTROOM.md's privacy row, errors.md and the mail basics (escaping in both parts, List-Unsubscribe, single-purpose tokens, verified-only, once-per-session, no addresses in logs). Every high and medium verified by reading the cited code before filing. No address, token or key value entered any context.

## Checked and found sound

- **Escaping.** `html/template` for the one template, so heading, lead, body, action and href are contextually escaped (`javascript:` neutralised, tested); the served pages escape their title and body; the confirmed-address page escapes the address.
- **Phishing resistance (#832).** Both mail-linked GETs render the app's own shell with no script and a POST behind a button; a scanner prefetch cannot act. `WritePage` sets `Referrer-Policy: no-referrer` and `Cache-Control: no-store` (from the sign-in hardening the same evening).
- **Unsubscribe.** No session required and none granted; a 122-bit random token; the statement flips exactly `notify_planned`; wrong token 404, mangled 400, both tested; the one-click POST reads the query, so RFC 8058 works.
- **Verified-only.** Structural in the targets query and again in `alertMail`; only the verification itself reaches a pending address. Banned members and the actor are excluded; the reminder excludes nobody on purpose.
- **Once.** The reminder's claim is the update, so a double tick, a restart or a second instance cannot re-mail; a moved session is deliberately re-armed.
- **Timezone.** Per rider with a documented server-zone fallback; the reminder is relative and needs no zone.
- **Failure handling.** Surfaced in the verify flow with the pending state rolled back; swallowed for alarms. No `Message: err.Error()` in the mail paths; no log line carries an address, a token or a body.
- **ADR-0030's lists.** All six triggers have exactly one call site; `notify` is the only mailer; nothing mails for DMs, friends, mentions, digests or marketing; the two opt-in switches narrow rather than override.
