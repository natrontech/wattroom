## The brief

Slice: `internal/auth` — sessions, the credential set, passkeys, the OAuth providers, synthetic
sign-in, and email verification.

Chosen because it was the last slice named as uncovered by the day's earlier passes and the highest
stakes remaining: a defect here is an account, not a number.

## The finding

**[#1163](https://github.com/natrontech/wattroom/issues/1163)** — `DeleteExpiredSessions` exists,
has an index built for it, and is called only from a test.

It is **not** a security hole: `GetSessionUser` filters `expires_at > now()`, so an expired row
authenticates nothing. What it leaves is an unbounded table and, more to the point, a permanent
undeclared record of when each rider signed in and from how many devices — against a codebase whose
canon elsewhere is that durable data is deliberate and bounded (ADR-0022, ADR-0034).

It is also the *only* one. Every other cleanup query has a production caller, checked rather than
assumed:

```
DeleteExpiredSessions  prod-callers=0
PruneChatImages        prod-callers=1
PruneChat              prod-callers=2
PruneDmImages          prod-callers=1
PruneDms               prod-callers=1
PruneSessionRecaps     prod-callers=1
```

One thing written and never connected, not a systemic gap.

## What was checked, and found sound

| Claim | Verdict |
| --- | --- |
| Session tokens are unguessable and not readable from the database | 32 bytes of `crypto/rand`, base64url; the table stores only `sha256` — `token_hash` is the primary key, the plaintext is never persisted |
| Cookie flags | `HttpOnly` and `SameSite=Lax` unconditionally; `Secure` conditional on the deploy scheme, with the lint suppression explaining exactly that |
| Login CSRF | The OAuth callback requires a state cookie that exists, is non-empty, and equals the `state` query parameter — without it "any link could complete a login" |
| The link-vs-login intent cannot be forged | Carried as a prefix *inside* the state, so it inherits the cookie's proof rather than needing a second cookie. `randomToken`'s alphabet cannot contain the separator |
| Synthetic sign-in cannot be triggered by a link | POST-only and bearer-authenticated, compared with `subtle.ConstantTimeCompare`, and deliberately absent from `/api/auth/providers` |
| Passkey ceremonies are single-use | `take` deletes before it checks expiry, so a replay finds nothing |
| Passkey challenge store cannot be flooded | 10-minute TTL, swept on write *before* the ceiling is tested, so the cap counts live ceremonies rather than aged-out debris |
| Relying party is derived, not configured twice | RP ID is the hostname of `WATTROOM_BASE_URL`; extra origins are an explicit env allowlist, unset in production |
| Email verification cannot be replayed or guessed | A hashed single-use token, 24 h TTL, resend throttled |
| Email verification cannot enumerate accounts | Expired, already used and never-ours all return one identical answer |
| A signed-in account cannot be a mail cannon | `budget.go` — a per-account ceiling, added because the resend cooldown is keyed on the address and changing the address walked straight past it (#827) |
| No password to get wrong | There is no password anywhere: ADR-0029's credential set is providers plus passkeys, email is recovery only. The absence of `bcrypt`/`argon2` is the design, not an omission |

## What was not covered

The sealing half, per the exclusion above. Session *fixation* was reasoned about only from the code:
`startSession` issues a fresh token on every sign-in, so there is no pre-authentication cookie to
adopt, but nothing was exercised in a browser. Nothing here says anything about behaviour under a
real OAuth provider — the providers were read, not driven.
