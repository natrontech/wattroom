# Audit: signing in and the account's security surface (2026-09-09)

**Slice.** `server/internal/auth/` (sessions, cookies, the OAuth providers, passkeys, email verification, the dev login, budgets, CSRF, logout, `/api/me`), the credential-set paths in `account/`, `RequireUser` and the SPA fallback, the secret sealing of stored tokens (ADR-0035), the HTTP hardening in `main.go`/`spa.go`; on the web, `/login`, `account.svelte.ts`, the verify-email gate, `PasskeyList`, `api.ts`'s 401 handling and the root layout's gating.

**Excluded.** Strava's data flows beyond the token seal, the desktop shell's own sign-in, DMs, rooms, rides. Open decisions reported on, not re-decided: #1493, #1507.

**Method.** One read-only Explore agent at `42c52583`+ against WATTROOM.md, ADR-0009/0029/0030/0035, errors.md and the ASVS basics; every finding verified by reading the cited code before filing. No secret or token value entered any context.

## Checked and found sound

- **Session cookies**: `HttpOnly` and `SameSite=Lax` unconditionally, `Secure` with an https base URL; a fresh random token on every sign-in (no fixation); logout is a server-side row delete that still checks Origin; only the SHA-256 is stored.
- **CSRF**: one boundary, `RequireUser`, refusing a mismatched Origin on mutating methods, with a test that proves reads are untouched.
- **OAuth callbacks**: state matched against an HttpOnly cookie (now in constant time); the link intent rides inside the state; an unknown provider is 404 before anything else; the redirect URI is server-built from the base URL. Linking never mints a session and refuses an identity owned elsewhere, including under the unique-violation race.
- **Passkeys**: single-use challenges (taken before the expiry check), a one-shot cookie cleared on spend, a bounded store answering 503 `rate_limited`, RP id and origins from the base URL, the signature counter written back on every login.
- **Verification token**: 32 bytes from `crypto/rand`, stored hashed, promoted by one UPDATE that is its own expiry check and clear; 24 h TTL; GET→form→POST so a mail scanner cannot confirm; the resend window is server-side; a failed send is rolled back; a partial unique index keeps one verified address per account.
- **Credential-set invariant**: one "last credential" query under `select … for update` for both removal paths; 409 `conflict`.
- **Status semantics**: nothing answered 401 for 403 or the reverse; 404 not 401 for an unconfigured provider; 404 not 403 for another account's passkey; 429 for the per-account passkey cap; 503 for the shared challenge store.
- **Logs**: no token, cookie, address or code on any line in `auth/`, `secrets/` or `notify/`; no `Message: err.Error()`.
- **Secret sealing** (ADR-0035): AES-256-GCM with a fresh nonce; an unusable key exits at boot; the backfill is off the boot path with a budget.
- **SPA gating**: the frame is held with the mark while `/api/me` is in flight; redirects use `replaceState`; only `unauthorized` signs the rider out — a 500 or a network failure keeps them in the room.
