# Audit: messages and notifications — 2026-09-10

**Slice.** `/messages` (the thread list, unread marks, the "N new" divider), direct messages (`/messages/dm/[peer]`: sending, the backlog, edits, reactions, images and GIFs, the composer, refusals, who may message whom), the DM heads poll and the sidebar's DM entries, notifications (ADR-0042: announce, away vs in front, the reply-from-notification path), and the server side (`server/internal/dms`, limits, retention, export, privacy).
**Excluded** (audited already): the room chat place itself, presence and the friends panel, crews, the HUD, rides.
**Method.** One Explore agent at `bd8b9598`, read-only against WATTROOM.md, docs/SPEC.md, ADR-0012, ADR-0042 and the rules; the two highs verified by reading the cited SQL and page code before filing. Nothing was observed in a running app.

## Checked and found sound

- **The friendship gate is in SQL, not in a handler.** `SendDm` and the image insert both carry `exists(... friendships ... status = 'accepted' ...)`, so no send path skips it; `TestDmsAreFriendsOnly` pins it.
- **Every read is pair-scoped by `least`/`greatest`** — the list, one message, edits, reactions, and `GetDmImage`'s sender-or-recipient predicate. A foreign id 404s rather than confirming it exists.
- **A stranger cannot address you and cannot enumerate you.** Heads are scoped to the caller; `GET /api/dms/{random}` is an empty thread with no oracle; the refusals are identical whether or not the target exists.
- **No read receipts, no typing indicators, no server-side "seen"** — ADR-0012's promise holds; "seen" is a localStorage stamp.
- **Retention matches the privacy page.** `PruneDms` runs on every send, `PruneDmImages` after it and after every upload, reactions cascade, and a deleted account takes both sides.
- **ADR-0042's "not looking" rule** — `document.hidden || !document.hasFocus()` on both platforms; away → OS notification, visible → toast; the DM's `reading` flag is the open thread in a front window, with both halves tested.
- **Announce-once across tabs and paths**; the first heads poll after sign-in is silent, and `stop()` clears the timer and badges on sign-out (#1781).
- **Focus rules** — the composer focuses on mount and on navigation with `preventScroll`, never on a poll; `chat-focus.spec.ts` asserts both.
- **Four states in the thread body**; the image trust boundary is one function (`ReadImageUpload` / `ServeImmutableImage`) shared with room chat; edits are sender-only and text-only with 404 and 403 separated.
- **Thread ordering and unread marks**: unread first, then last-spoken, then name; a count for a room and a dot for a DM, both on the muted token.
- **`/messages` is in the phone sweep**, the layout swaps list-for-thread below `md` with a back link, and the sidebar DM rows are `min-h-11` on a phone; right-click covers the head, the message row and the person in it — the one gap is the picture (#1817).
- **The desktop reply field's trust boundary**: every string clipped, only a same-origin path accepted, as ADR-0042 requires.
